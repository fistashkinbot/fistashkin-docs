# V2 Update — 13.09.2026

## Interface and Profile

- The entire bot interface has been rewritten and adapted for Discord Components V2.
- Interactive Components V2 correctly restore tracking on the first click after a bot restart if the button or list is still active.
- Server settings check the message owner and the current "Manage Server" permission on every action.
- Repeated navigation in the profile, server info, leaderboards, role shop, and paginators has been sped up by caching ready-made components.
- Profile achievement tabs again display achievements from the old numeric database format.
- The avatar context command has been moved to Components V2: links to PNG, JPG, WebP, GIF for animated avatars, and the standard avatar are displayed as buttons.

## Economy

- A bonus claim button has been added to the `balance` command.
- The balance bonus has a permanent `1` hour cooldown: the amount and remaining time are stored in the database and are not reset on restart.
- The `work` command also has a permanent `1` hour cooldown with the next use time displayed.
- The "no commission" case buff applies to currency transfers between members until it expires.
- The role shop is split into pages of `5` items; buttons are available to go back, forward, and to a specified page.
- Each shop item is displayed as a separate Components V2 section with the role, price, and purchase button.
- After a successful purchase, the shop menu remains open on the current page, and the purchase confirmation is sent only to the buyer.
- A limit of `25` roles per server has been introduced for the shop: it is checked in settings and additionally enforced when writing to the database.
- If a shop role is deleted on the server, its record is immediately removed from the database. After the bot starts and then every `15` minutes, the shop is reconciled with the server's current roles.

## Server Settings

- In the role shop settings, you can add roles, remove them, and change the price of an already added role.
- Before adding, the role's existence, its position relative to the highest administrator role, and unavailable Discord service roles are checked.
- When the shop limit is reached, a localized message is displayed; the check is repeated before opening the price form and when saving it.
- The main settings menu contains sections for temporary rooms, shop, logs, AutoMod, moderation, ranking, greetings, levels, and server language.
- A greetings section has been added: it allows enabling or disabling welcome messages, selecting text channels, and separately editing welcome and goodbye templates.
- The welcome and goodbye templates support `[memberMention]`, `[member]`, `[guild]`, and `[guildMembers]`; settings show the current channels, and an empty template disables the corresponding message.
- Welcome and goodbye messages are not sent for bots, and only users may be mentioned in the texts, without roles or `@everyone`.
- In the level notification settings, you can enable or disable messages, select a text channel, and specify a custom template. The template supports `[memberMention]`, `[member]`, `[lvl]`, and `[xp]`; an empty value restores the default text.
- In the moderation settings, you can enable or disable automatic punishment for warnings, set a limit from `1` to `999`, choose the action `ban`, `kick`, or `mute`, and set the mute duration from `1` second to `28` days.
- The same section configures sending punishment notifications to members' direct messages.

## Utilities

- In the user card, the biography is edited through a modal window: an empty value deletes the biography, and updated data is immediately displayed in the profile.
- Ready-made Components V2 views are cached for user info and server info, and the profile cache is cleared after the biography is changed.
- The random emoji command has been replaced with `get-emoji`: it accepts a custom Discord emoji, displays its PNG or GIF, and provides a direct download link.
- `get-emoji` is available only on a server and outputs a localized error for regular Unicode emojis.

## Entertainment

- The source of anime images for `interaction` and `anime-chan` has been moved from Waifu.pics to Nekos Best API v2.
- The client has been renamed to `nekos_api`; the image retrieval function is called `nekos_get_image` and extracts the URL from `results[0].url`.
- The Nekos Best client sends the required `User-Agent`.
- Categories missing from Nekos Best have been excluded from the command options: `lick`, `megumin`, `shinobu`, and `awoo`.
- Added games: `truth-lie`, `dice-friend`, `guess-number`, `duel`, `russian-roulette`, `hangman`, `tic-tac-toe`, `rps`, and `guess-door`.
- Network games send an invitation to a specific member, check participation and turn order, and do not allow playing with yourself or a bot.
- Game interfaces are designed with Components V2: buttons and lists are disabled after the session ends, and private intermediate responses do not close the game message.
- "Hangman" uses a letter selection list; separate alphabets and word sets have been added for Russian, English, and Ukrainian.
- All game cards, buttons, invitations, errors, hints, and results are localized for Russian, English, and Ukrainian.
- In "Truth or Lie", answer correctness is now stored separately from the statement text, so it does not depend on the locale and is determined correctly for each fact.

## Marriage System

- A marriage system has been added with commands for proposing, divorcing, viewing the current marriage, and viewing the server's general list of couples.
- Proposal and divorce are confirmed with interactive Components V2 buttons; only the mentioned member can accept or decline a proposal.
- Administrators have commands to forcibly marry and divorce specified members.
- Couple data is stored as mirrored records in SQLite and created or deleted atomically, without the risk of leaving an incomplete marriage.
- The marriage list supports pagination, and removing a member from the server clears related records.
- The marriage cog is displayed in help and has a localized name, description, and interface.

## Logs and Moderation

- Bot logs are saved without ANSI colors, so the sent file is read correctly outside the console.
- The ban command has received updated notification handling: sending a message to the member is controlled by a separate server panel setting.

## Fight Club

- Fight Club has been reworked into a risk-choice game: a hit to the legs — `60%` and `x1.4`, to the body — `40%` and `x2.2`, to the head — `20%` and `x4.5`.
- The chance and multiplier are visible on the button before the bet is confirmed.

## Temporary Voice Rooms

- Temporary rooms have received a permanent Components V2 control panel with native emojis and a description of all actions.
- When creating the panel, the bot mentions the room creator; only user pings are allowed for this message, without role or `@everyone` mentions.
- The panel does not use the Components V2 accent color bar.
- The room owner can change the name and member limit, remove the limit, open or close the room for everyone, disconnect or mute a member, grant or remove access, send a one-time invite, and transfer control.
- Control is available only to the owner who is in the room; for each action, the owner's rights, the presence of the selected member in the room, and the bot's permissions are checked.
- A dropdown `⚙️ Settings` has appeared in the panel: through it, the owner changes the bitrate and sets the delay for deleting an empty room in minutes.
- The empty-room deletion setting is stored in the database. The countdown starts immediately after the last member leaves and resets when a member appears in the room again.
- The cleanup task runs every `5` seconds, so deletion occurs with an error of no more than five seconds from the set time.
- If no deletion time is set, an empty temporary room is deleted immediately.
- When deleting a room, the bot specifies a localized reason in the Discord audit log.
- If a channel is deleted by an administrator while the bot is running, its record is immediately removed from the database. After a restart, the bot additionally reconciles saved channels with the Discord API and removes from the database only records about truly missing or non-voice channels.
- The temporary room panel buttons are not disabled by the general component timeout.

## Moderation

- The `warn` command now has a mandatory warning duration: formats `10m`, `2h`, `7d`, and Russian abbreviations `10м`, `2ч`, `7д` are supported.
- Temporary warnings contain the issue date and expiration date, displayed in `warnings`.
- Expired warnings are not counted toward the limit and are automatically removed from the database every `15` minutes.
- The `clearwarn` command now removes one active warning by number from the `warnings` list instead of clearing all at once.

## Case System

### Server Progress

- The `cases` command has received a server-wide case level from `1` to `10`.
- All openings are counted in permanent storage: server experience and total openings are displayed.
- A regular case costs `500` FC and adds `+1` server case experience.
- The daily case is free, available once per UTC day, and adds `+0.7` experience.
- Level thresholds: `0`, `20`, `50`, `150`, `400`, `800`, `1500`, `2500`, `6000`, and `10000` experience.

### Rewards

- A regular case gives from `125` to `1600` FC at level one, and the daily case gives from `75` to `600` FC.
- Server levels increase the minimum and maximum currency reward.
- Starting from level 3, a no-commission buff for transfers can drop, lasting from `1` to `7` days.
- Starting from level 5, a role from the server shop can drop, lasting from `3` to `14` days.
- If there is no suitable role or the bot cannot grant it, compensation of `20%` of the currency reward is awarded instead.
- Temporary roles are stored in the database and automatically removed after expiration.
