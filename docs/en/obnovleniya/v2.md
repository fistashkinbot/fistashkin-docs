# Update V2 — 13.09.2026

{% hint style="warning" %}
**Open Beta Test**

Version V2 is currently in open beta testing.  
Patches and updates will be released approximately once a month.
{% endhint %}

## Interface and Profile

- The entire bot interface has been rewritten and adapted for Discord Components V2.
- Interactive Components V2 correctly restore tracking on the first click after a bot restart if the button or select menu is still active.
- Server settings verify the message owner and the current “Manage Server” permission on every action.
- Repeated navigation in profile, server info, leaderboards, role shop and paginators has been sped up by caching ready-made components.
- Profile achievement tabs once again display achievements stored in the old numeric database format.
- The avatar context command has been moved to Components V2: links to PNG, JPG, WebP, GIF for animated avatars and the standard avatar are shown as buttons.

## Economy

- A bonus claim button has been added to the `balance` command.
- The balance bonus has a permanent `1`-hour cooldown: the amount and remaining time are stored in the database and are not reset on restart.
- The `work` command also has a permanent `1`-hour cooldown with the next available time displayed.
- The “no commission” buff from cases is applied to currency transfers between members until it expires.
- The role shop is split into pages of `5` items; back, forward and jump-to-page buttons are available.
- Each shop item is displayed as a separate Components V2 section with the role, price and a purchase button.
- After a successful purchase the shop menu stays open on the current page, and the purchase confirmation is sent only to the buyer.
- A limit of `25` roles per server has been introduced for the shop: it is checked in settings and additionally protected on database write.
- If a shop role is deleted on the server, its record is immediately removed from the database. After bot startup and every `15` minutes the shop is synced with the server’s current roles.

## Server Settings

- In the role shop settings you can add roles, remove them and change the price of an already added role.
- Before adding a role its existence, position relative to the administrator’s highest role, and Discord’s restricted system roles are checked.
- When the shop limit is reached a localised message is shown; the check is repeated before opening the price form and when saving it.
- The main settings menu now contains sections for temporary rooms, shop, logs, AutoMod, moderation, rating, welcomes, levels and server language.
- A welcome section has been added: you can enable or disable welcome messages, choose text channels and separately edit welcome and goodbye templates.
- Welcome and goodbye templates support `[memberMention]`, `[member]`, `[guild]` and `[guildMembers]`; settings show the current channels, and an empty template disables the corresponding message.
- Welcomes and goodbyes are not sent for bots, and only user mentions are allowed in the text — no roles or `@everyone`.
- In level-up notification settings you can enable or disable messages, choose a text channel and set a custom template. The template supports `[memberMention]`, `[member]`, `[lvl]` and `[xp]`; an empty value restores the default text.
- In moderation settings you can enable or disable automatic punishment for warnings, set a limit from `1` to `999`, choose the action `ban`, `kick` or `mute` and set the mute duration from `1` second to `28` days.
- Sending punishment notifications to members’ DMs is also configured there.

## Utilities

- In the user card the biography is edited via a modal window: an empty value removes the biography, and the updated data is immediately shown in the profile.
- Ready-made Components V2 views for user info and server info are cached; the profile cache is cleared after a biography change.
- The random emoji command has been replaced by `get-emoji`: it accepts a custom Discord emoji, shows its PNG or GIF and provides a direct download link.
- `get-emoji` is available only on servers and returns a localised error for ordinary Unicode emojis.

## Entertainment

- The anime image source for `interaction` and `anime-chan` has been moved from Waifu.pics to Nekos Best API v2.
- The client has been renamed to `nekos_api`; the image retrieval function is called `nekos_get_image` and extracts the URL from `results[0].url`.
- The Nekos Best client sends the required `User-Agent`.
- Categories missing from Nekos Best have been removed from the command options: `lick`, `megumin`, `shinobu` and `awoo`.
- New games have been added: `truth-or-lie`, `dice-friend`, `guess-number`, `duel`, `russian-roulette`, `hangman`, `tic-tac-toe`, `rps` and `guess-door`.
- Multiplayer games send an invitation to a specific member, check participation and turn order, and do not allow playing with yourself or a bot.
- Game interfaces are built with Components V2: buttons and selects are disabled after the session ends, and private intermediate replies do not close the game message.
- “Hangman” uses a letter-select menu; dedicated alphabets and word lists have been added for Russian, English and Ukrainian.
- All game cards, buttons, invitations, errors, hints and results are localised for Russian, English and Ukrainian.
- In “Truth or Lie” the correctness of the answer is now stored separately from the statement text, so it no longer depends on the locale and is correctly determined for every fact.

## Marriage System

- A marriage system has been added with commands for proposal, divorce, viewing the current marriage and the server’s full couple list.
- Proposal and divorce are confirmed with interactive Components V2 buttons; only the invited member can accept or decline a proposal.
- Administrators have commands for forced marriage and forced divorce between specified members.
- Couple data is stored as mirrored SQLite records and is created or deleted atomically, eliminating the risk of leaving an incomplete marriage.
- The marriage list supports page navigation, and removing a member from the server clears the related records.
- The marriage cog appears in the help menu and has a localised name, description and interface.

## Logs and Moderation

- Bot logs are saved without ANSI colours, so the uploaded file is readable outside the console.
- The ban command has updated notification handling: sending a message to the member is controlled by a separate server panel setting.

## Fighting Club

- The Fighting Club has been redesigned as a risk-choice game: legs — `60%` and `x1.4`, body — `40%` and `x2.2`, head — `20%` and `x4.5`.
- Chance and multiplier are visible on the button before the bet is confirmed.

## Temporary Voice Rooms

- Temporary rooms now have a permanent Components V2 control panel with native emojis and a description of every action.
- When the panel is created the bot mentions the room creator; only a user ping is allowed for this message — no role or `@everyone` mentions.
- The panel does not use the accent colour bar of Components V2.
- The room owner can change the name and member limit, remove the limit, open or close the room for everyone, disconnect or mute a member, grant or revoke access, send a one-time invite and transfer ownership.
- Control is available only to the owner who is currently in the room; every action checks owner permissions, the presence of the selected member in the room and the bot’s permissions.
- A `⚙️ Settings` dropdown has been added to the panel: through it the owner can change the bitrate and set the empty-room deletion delay in minutes.
- The empty-room deletion setting is stored in the database. The countdown starts as soon as the last member leaves and is reset when someone joins again.
- The cleanup task runs every `5` seconds, so deletion occurs with an accuracy of no more than five seconds from the set time.
- If no deletion time is set, an empty temporary room is deleted immediately.
- When a room is deleted the bot writes a localised reason to the Discord audit log.
- If a channel is deleted by an administrator while the bot is running, its record is immediately removed from the database. After a restart the bot additionally syncs saved channels with the Discord API and removes only records of truly missing or non-voice channels.
- Temporary-room panel buttons are not disabled by the general component timeout.

## Moderation

- The `warn` command now requires a warning duration: formats `10m`, `2h`, `7d` and the Russian abbreviations `10м`, `2ч`, `7д` are supported.
- Temporary warnings store the issue date and the expiry date, which are shown in `warns`.
- Expired warnings are not counted toward the limit and are automatically removed from the database every `15` minutes.
- The `unwarn` command now removes a single active warning by its number from the `warns` list instead of clearing all at once.

## Case System

### Server Progress

- The `cases` command now has a server-wide case level from `1` to `10`.
- All openings are recorded in permanent storage: server experience and total open count are displayed.
- A regular case costs `500` FC and adds `+1` experience to the server case.
- The daily case is free, available once per UTC day and adds `+0.7` experience.
- Level thresholds: `0`, `20`, `50`, `150`, `400`, `800`, `1500`, `2500`, `6000` and `10000` experience.

### Rewards

- A regular case gives from `125` to `1600` FC at level 1, a daily case from `75` to `600` FC.
- Server levels increase the minimum and maximum currency reward.
- Starting from level 3 a no-commission transfer buff lasting from `1` to `7` days can drop.
- Starting from level 5 a shop role lasting from `3` to `14` days can drop.
- If no suitable role exists or the bot cannot assign it, a compensation of `20%` of the currency reward is given instead.
- Temporary roles are stored in the database and are automatically removed after they expire.

# Update V2 — 03.10.2026

## Settings Menu

- The main settings menu is now a status summary: the state and brief information about configured server systems are visible before entering any section.
- Button labels match the category names; sections and their components follow a unified Components V2 template.
- The role shop, logs, AutoMod, temporary channels, moderation, rating, welcomes and levels screens show current statuses and grouped actions.
- Changing settings via buttons and modals updates the open screen when the current interaction scenario supports it.
- Deleting AutoMod rules and temporary-channel triggers requires confirmation; a “delete all” action has been added for voice triggers.
- After removing a role from the shop the last available page of the list is shown; role-management buttons display more specific actions.
- Confirmations, statuses, previews and settings labels have been translated into Russian, English and Ukrainian.

## Temporary Rooms

- The temporary-rooms settings screen shows the current system status, the number of active triggers and the list of source voice channels.
- Adding and removing triggers is done through Components V2; deletion requires confirmation.
- Mass deletion of all voice triggers on the server is available with a single confirmed button.
- After changes the trigger list and system status are updated without closing the menu.
- Bitrate and empty-room deletion delay settings are available both from the room panel and from the server settings section.

## Moderation

- The moderation screen displays the status of automatic punishments, the current warning limit, the selected action and the mute duration.
- Enabling/disabling auto-punishment, changing the limit, action and mute duration is done directly from the menu without extra commands.
- The setting for sending punishment notifications to members’ DMs is a separate toggle with status.
- All changes are immediately reflected in the status summary of the main settings menu.

## AutoMod

- The AutoMod screen shows the list of active rules with a short description of type and status.
- Adding, editing and deleting rules supports confirmation before deletion.
- After a rule is deleted the list is refreshed; when there are no rules the corresponding status is shown.
- The AutoMod interface is fully localised and follows the unified Components V2 template.

## Server Language

- The server-language settings display the currently selected language and the list of available options (Russian, English, Ukrainian).
- Language change is performed with a single button; after selection the bot’s interface on the server immediately switches to the new locale.
- The selected language status is shown in the main settings menu.
- All texts of the section are localised.

## Command Availability

- The slash command `info` and the game `minesweeper` are available both in DMs with the bot and on servers.
- All other slash commands and the context menu are restricted to servers; extra commands no longer appear in DMs.
- The no-server scenario for `info` and `minesweeper` has been handled in the common cooldown mechanism.

## Profiles and Biographies

- Random placeholder texts have been added for an empty biography: `10` variants each for the user’s own profile, another member’s profile and the bot’s profile.
- Own-profile hints suggest adding a description via a button; variants for other members and bots use separate wording.
- All biography variants are localised for RU/EN/UK. Badges and the badge row are not shown on bot profiles.
- If a game activity has no start time, the profile shows its name and type without a timestamp instead of a `NoneType` error.

## Refactoring and Stability

- Gradual refactoring of the own code in `core`, `classes`, `services`, `extensions`, `helpers` and `utils` continues: imports and formatting have been unified, confirmed annotations added, some expressions simplified and unused elements removed.
- A common path helper has been extracted in the DB layer; schema initialisation and migrations are gathered in `DatabaseInitializer` while keeping compatible public functions.
- Several schema and query mismatches have been fixed: the blacklist check is now connected to the existing cacheable DB query, and queries use the actual column name `member_id`.
- Background-operation errors in a number of handlers are written through the logger; error messages are no longer printed directly to the console in the affected tasks.
- Further refactoring of the music module has been skipped by request; third-party library copies were not modified.

## Game Screens

- In the NSFW, “Animals” and “Anime-chan” commands a “New image” button has been added: it reloads an image of the selected category and updates the original message.
- Only the user who invoked the command can refresh the image; labels and error messages are localised for Russian, English and Ukrainian.
- After the result of slots, coin flip and Fighting Club a “Back to main screen” button appears: it returns to the action selection while keeping the original bet amount.
- After a win or loss in Minesweeper the button starts a new board with a new mine layout.
- After opening a case the button returns to the case menu with the updated server progress.
- The return is performed in the same message; the buttons are available only to the game author and are localised for Russian, English and Ukrainian.

## Checks

- Python files changed in the corresponding stages passed Pylance syntax checks; for several packages lines longer than `100` characters and trailing whitespace were additionally checked.
- Localisation JSON files were validated for correctness and duplicate keys; repeated keys were removed. The new profile text sets contain all variants in every locale.
